# DealFlow

**DealFlow — quote-to-cash that shows its work.** DealFlow is a sales-operations workspace that turns a quotation into an approved, customer-confirmed, stock-aware, billed, paid, and auditable deal. Deterministic pricing, approval, allocation, and proration engines explain every result; role-aware dashboards, deal-health alerts, operational tasks, reports, XLSX downloads, branded PDFs, Cashfree sandbox checkout, and repeatable demo reset complete the flow.

## Run locally

Prerequisites: Node.js 20+, npm, and Docker Desktop.

```bash
git clone https://github.com/Anant-0705/DealFlow.git
cd DealFlow
copy .env.example .env
docker compose up -d postgres
npm install
npm run db:reset
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). To run the complete app in Docker, use `docker compose up --build`. `npm run db:reset` and Settings → System → Reset Demo Data delete all current DealFlow records before recreating the seed; use them only with the demo database.

Set `RESEND_API_KEY` (and optionally `RESEND_FROM`) to email customer invitations and password resets. Without those keys the app still creates the invitation and shows the one-time link in Settings → Customers. Use a verified Resend domain in production; `onboarding@resend.dev` only delivers to the Resend account owner.

Set `CASHFREE_APP_ID` and `CASHFREE_SECRET_KEY` to enable hosted checkout on unpaid invoices. Keep `CASHFREE_ENV=sandbox` and the sandbox API URL while testing. `NEXTAUTH_URL` must be the public HTTPS origin in a deployed environment so Cashfree can call `/api/webhooks/cashfree`; the return page and webhook both re-check Cashfree's order status before recording money.

Customer self-registration is approval-based. From the sign-in page, a customer selects **Need an account?**, enters their company name, primary contact email, phone, GSTIN, and billing address, then selects **Notify admin**. Administrators see the pending request on the notification bell, dashboard, and Settings → Customers. Approval creates the customer company immediately for Sales Reps and sends a Resend invitation so the contact chooses their own password. Portal passwords are never generated by an administrator.

### Customer onboarding flow

1. Customer opens `/login`, selects **Need an account?**, completes the request, and selects **Notify admin**.
2. An Administrator opens the notification bell or Settings → Customers → Customer account requests.
3. The Administrator verifies the details, selects a tier, then chooses **Approve & invite** (or dismisses the request).
4. The approved company appears immediately in the customer selector when a Sales Rep creates a quotation.
5. The customer opens the one-time email invitation, chooses their name and password, and signs in to the portal.

## Demo flows

1. Clean flow: Ravi creates an Acme quote, confirms its policy route, sends it, the customer confirms, Operations accepts the stock split and marks an allocation shipped, and the customer or Finance pays that shipment invoice through Cashfree sandbox checkout.

## Known limitations

- Customer invitations and password resets are sent with Resend when `RESEND_API_KEY` is set. Without it, Settings → Customers still shows the one-time invite link. Slack, WhatsApp, and quote-send emails are still in-app only.
- Branded quote and invoice downloads are generated server-side; A4 browser print previews remain available.
- Cashfree is configured for sandbox by default. Production requires live keys, a whitelisted HTTPS domain, and production webhook configuration.
- Billing runs are user-triggered rather than scheduled by a worker or cron service.
- Currency and company scope are currently INR and one workspace.
- Deal-health rules run when the page/dashboard loads; a large deployment should precompute them asynchronously.
